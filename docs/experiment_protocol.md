# Experiment Protocol

The main comparison keeps model, prompts, tools, task order, evaluator, and resource limits fixed. Memory condition is the treatment variable.

Primary metric: Repeated Failure Rate.

Mandatory safety/correctness metric: False Advice Rate.

Tasks are chronological. A run can use only memory generated by earlier tasks. Future task labels, solutions, and outcomes must never enter the memory available to an earlier run.

## Sprint 3D-A pre-Gate-B1 freeze correction

The bounded development contract is frozen as follows. B0 receives only the
task prompt. O1 receives the single validated ideal recovery intervention for
the task, once at `task_start` and before the first model request. The frozen
GS-R014 recovery wording and provenance remain unchanged. The later treatment
condition T uses this same intervention boundary with retrieved guidance.

The fixed `max_actions=20`, `max_requests=24`, agent/model timeouts of 300
seconds, tool retries of 3, and five-second provider pacing remain unchanged.
When PydanticAI reaches one of the configured action/request limits, the run
is recorded as bounded termination (`budget_exhausted`) with the responsible
budget and configured limit. This is a valid experimental outcome; provider,
infrastructure, malformed-tool, and timeout failures retain their normal
classification and are never converted to budget exhaustion.

The B0/O1 provider smoke checks execution plumbing: one run per condition,
zero B0 advice, one GS-R014 O1 intervention at the task-start boundary,
matching runtime and pacing contracts, and complete artifacts/raw evidence.
Objective task success is not required, budget exhaustion alone does not fail
the smoke, `gate_b1_evaluated` remains false, and no T execution is included.
Previous provider-smoke runs are development evidence only; no Gate B1 result
has been produced.
